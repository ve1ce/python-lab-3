# Лабораторная работа №3

Приложение для изучения иностранных языков: настольная версия PySide6 и веб-версия FastAPI с общей базой PostgreSQL 17 в Docker Compose.

Проект разработан для лабораторной работы «Работа с графическим интерфейсом на Python». Выполнены уровни Rare, Medium и Well-done.

## Возможности обеих версий

- Главная: количество слов, завершённых тренировок и дней активности, график за семь дней, последние действия.
- Словарь: добавление, удаление и поиск по английскому слову или переводу. Одинаковая проверка пустых полей, повторных слов без учёта регистра и ограничения в 80 символов.
- Практика: лёгкий уровень — 5 вопросов, средний — 10, сложный — 15. Нужны соответствующее количество слов и минимум четыре разных перевода. Слова в тренировке не повторяются; доступны четыре варианта ответа, подсветка, прогресс и итоговый счёт.
- История: добавления и удаления слов, результаты тренировок, дата и время. Новые события отображаются первыми.

Оформление настольного приложения задаётся QSS, график строится Matplotlib. Веб-версия использует Jinja2 и CSS.

## Архитектура и структура

```text
main.py                  # главное окно PySide6, запуск и навигация
app/
  database.py            # PostgreSQL: подключение, таблицы, репозитории, SQL и транзакции
  services.py            # сервис словаря, сигналы Qt, общая подготовка тренировок
  exceptions.py          # ошибка проверки словаря
  ui/                    # четыре страницы, widgets.py и styles.qss
web/
  main.py                # маршруты FastAPI и запуск веб-приложения
  templates/             # Jinja2
  static/                # CSS
compose.yaml             # существующий PostgreSQL 17 и постоянный volume
requirements.txt         # общие зависимости
tests/                   # проверки репозиториев, сервисов, маршрутов и двух интерфейсов
```

Оба интерфейса обращаются к `app/database.py`. Дублирующий `web/database.py` удалён. ORM и дополнительные серверы не используются.

Общие таблицы:

- `words` — слова и переводы; уникальный индекс по `LOWER(word)`.
- `activities` — единая история, на основании которой рассчитывается статистика.
- `practice_sessions` — UUID тренировки, снимок вопросов и вариантов ответа, текущий вопрос, выбранный ответ и счёт.

Изменение словаря и запись события выполняются в одной транзакции. Интерфейсы не записывают события самостоятельно: Qt-сигнал только обновляет страницы. Ответы и переходы тренировки обрабатываются общей функцией с `SELECT ... FOR UPDATE`; повторная или одновременная отправка одного шага не увеличивает счёт и не дублирует результат. Завершение и запись истории также атомарны. Удаление слова не изменяет вопросы уже начатой тренировки.

При каждом выборе раздела настольная версия заново читает данные из PostgreSQL, включая повторное нажатие текущего раздела. После локальных операций связанные страницы обновляются сигналом. Поэтому изменения веб-версии видны при переходе на «Словарь», «Главную», «Историю» или «Практику». В браузере данные перечитываются при новом запросе или обновлении страницы. Статистика обоих интерфейсов использует один SQL-код и согласованный снимок данных.

## Установка и общая база

Нужны Python с поддержкой зависимостей, Docker Desktop / Docker Engine и Docker Compose. Команды выполняются из корня проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

В Linux/macOS активация: `source .venv/bin/activate`.

Используйте существующий `.env`. Для новой установки минимально требуется:

```dotenv
POSTGRES_PASSWORD=your_local_password
```

Оба приложения читают `.env` из корня проекта независимо от текущей рабочей папки. Переменные окружения имеют приоритет. Дополнительные настройки и значения по умолчанию:

| Переменная | Значение по умолчанию |
| --- | --- |
| `POSTGRES_HOST` | `127.0.0.1` |
| `POSTGRES_PORT` | `5433` |
| `POSTGRES_DB` | `language_lab` |
| `POSTGRES_USER` | `lab_user` |

Compose использует те же `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER` и пароль. Для существующего volume сохраняйте исходные имя БД, пользователя и пароль: изменение `.env` не меняет уже созданные учётные данные PostgreSQL.

Запустите Docker, затем PostgreSQL:

```powershell
docker compose up -d db
docker compose ps
docker compose exec db pg_isready -U lab_user -d language_lab
```

Если имя пользователя или БД настроены иначе, подставьте их в команду проверки. Дождитесь `accepting connections`.

## Запуск интерфейсов

Настольная версия:

```powershell
python main.py
```

Веб-версия во втором терминале с активированным окружением:

```powershell
python -m uvicorn web.main:app --reload
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Обе версии можно использовать одновременно.

Для выхода из настольной версии доступны «Файл → Выход» и Ctrl+Q. Веб-сервер останавливается Ctrl+C. PostgreSQL можно остановить командой `docker compose stop db`, сохранив данные.

## Сохранность данных

При запуске создаются только недостающие таблицы и индекс; существующая схема PostgreSQL совместима с прежней веб-версией. Восемь начальных слов добавляются только при первом создании таблицы `words`, а не при пустом словаре. Одновременная инициализация двух интерфейсов защищена транзакционной advisory-блокировкой.

Пользовательские записи PostgreSQL и volume `postgres_data` сохраняются. Не выполняйте `docker compose down -v` для обычного запуска или тестов.

SQLite больше не используется приложением или тестами. Старый `app.db` остаётся на диске без изменений; автоматического удаления или переноса его записей нет. Источником общих данных служит существующая PostgreSQL-база. При пустой истории настольная главная страница сохраняет демонстрационный график.

## Тестирование

При работающем PostgreSQL:

```powershell
python -m pytest -v
```

Тесты подключаются с настройками сервера из `.env` к служебной БД `postgres`, создают отдельную БД `language_lab_test_<случайный UUID>`, затем направляют в неё общий слой доступа обоих интерфейсов. Таблицы сбрасываются только внутри этой временной БД; после тестов она удаляется. Пользовательская БД не используется. У пользователя должны быть права `CREATEDB` (пользователь стандартного образа Compose ими располагает). Ошибка подключения или создания тестовой БД завершает проверки ошибкой; подмены основной БД нет.

Проверяются инициализация без потери записей, валидация, повторные операции, откат словаря и тренировок при ошибке записи истории, конкурентное завершение и сохранность вопросов активной тренировки.

`tests/test_shared.py` запускает реальные виджеты PySide6 без видимого окна (`QT_QPA_PLATFORM=offscreen`) и FastAPI TestClient с общей тестовой БД. Он проверяет слова и удаления в обе стороны, обновление страниц через навигацию, каждый уровень тренировки из обоих интерфейсов, общие результаты, историю и статистику. `tests/test_web.py` отдельно проверяет веб-страницы с подменой хранилища.

Для быстрой проверки веб-шаблонов без PostgreSQL:

```powershell
python -m pytest tests/test_web.py -v
```

Ручная проверка: добавьте слово в настольном словаре и обновите веб-словарь; затем добавьте другое слово в браузере и повторно выберите настольный «Словарь». Завершите тренировку, обновите веб-страницы «История» и «Главная», затем откройте эти же разделы в настольной версии: результат и счётчик тренировок должны совпадать.
